Agents move fast.
The way back is missing.

Coding agents now run shell commands, delete folders and touch databases. The tools around them were built to undo an edit, not to bring back a project that works.

Rewind gap

Claude Code's rewind does not cover the shell.

Its docs say checkpointing "does not track files modified by Bash commands". Changes made by commands like rm or mv cannot be undone through rewind.

Sources: Claude Code docs, eon.io

A user reported that an agent permanently deleted an entire production resource folder, and asked for help getting it back.

Source: Cursor community forum

Every bug fix starts with a failing test.

That is the whole idea of Time Machine, so the codebase lives by it. Before a fix, there is a test that shows the bug. The fix is done when that test passes and nothing else broke.

Two independent reviews of the engine found 17 bugs. Every one was fixed test first. The reviews also changed the design: verdicts are now bound to the exact save point they were made for, a store inside the project is refused, and restores never write through a symbolic link.

  • One engine. The CLI, the hooks, the MCP server and the web app call the same code, so they never disagree.
  • Decisions are written down as short records with the choice, the alternatives and the cost.
  • Planned is labelled Planned, on this site, in the docs and in the help text.
  • Synthetic data only. No real customer data in tests, logs or examples.

Gates, not dates.

Each stage starts when the one before it has met its gate. A gate is an outcome you can check, not a day on a calendar.

Now

Gate 1 · Engine and CLI

Done when: every acceptance test passes on macOS and Linux CI, the demo runs end to end, and your folder and current branch are byte for byte unchanged after every command.

Status: met. 384 automated tests pass in CI on macOS and Linux. Publishing timetm to npm is the last step.

Gate 2 · Web app

Done when: someone who does not use a terminal can go back to the last working version with one button, on the same engine as the CLI, in the web app.

Status: built. tm ui opens the web app from a source install and runs on your computer. Still to do: publish timetm to npm, and open checkout for the $50 key.

Gate 3 · Action connector

Starts only when: timetm is on npm and a stranger can reach a verified recovery branch, the design is signed off in writing, and the legal and data questions are settled.

What it would do: record what agents do in apps like Gmail, Slack, Notion and Calendar through Claude and ChatGPT, and reverse only what each app can really reverse. Every result would say what was not reversed.

To do this properly.

The CLI works. Turning it into something people can trust with their projects takes four things that time alone cannot buy.

  • Full time building.Focused time on the engine and the web app, instead of fitting it around other work.
  • Shipping the web app.Publishing to npm, opening checkout, and support and updates for people who pay once.
  • An outside security review.A tool that touches your code should be checked by someone other than the person who wrote it.
  • Support for design partners.Time and help for the first builders who use it on real projects and tell us where it breaks.
