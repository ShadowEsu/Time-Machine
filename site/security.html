Six rules the engine keeps.

These are built and tested today, on macOS and Linux CI. They apply to the CLI, the hooks and the MCP server, which all call the same engine.

01

Local first

The tm tool has no account and no server. Save points, logs, reports and the audit log live on your machine. We cannot see them.

02

No .env values stored

For config files like .env, only key names and a keyed fingerprint. Files that look like they hold a secret are skipped. Check logs are scrubbed of current secret values.

03

Signed save points

Each save point and each verdict is signed with a key on your machine. A changed save point gives ERROR, never PASS.

04

A separate copy

Checks run in a separate Git worktree with a clean environment and a time limit. The network is off when a sandbox can enforce it.

05

Never pushes, merges or deploys

Recover makes a new branch and a recovery copy. It never switches your folder. Switching is up to you.

06

Everything is logged

Every action goes in an append-only audit log in the store. Read it with tm log.

Outside your project.
On your machine.

If an agent runs rm -rf on your project, the save points are somewhere else.

~/.timemachine/          or $TM_HOME
├── key                  signs every save point
└── projects/
    └── 9f2c41d07a3be815/ hash of the path
        ├── objects/     files, stored once
        ├── checkpoints/ signed manifests
        ├── bundles/     Git bundles
        ├── logs/        check logs
        ├── reports/     recovery reports
        ├── audit.jsonl  append only
        └── project.json
  • One folder per project, named by a hash of the project path. A store inside the project is refused.
  • Code survives the folder. Each save point is a Git commit pinned at refs/tm/<id>, and also written as a Git bundle into the store. Deleting your project does not delete its save points.
  • Files are stored once by content and compressed, so repeats cost nothing. Check disk use with du -sh ~/.timemachine.
  • Keep the key. ~/.timemachine/key signs every save point, so edits by other tools are caught. Save points are not encrypted: anyone who can read your disk can read them.

Key names only.
Never .env values.

After a recovery, you set secret values again by hand. The report lists each one, so nothing is a surprise.

  • For files like .env, Time Machine saves the key names and a keyed fingerprint. The fingerprint shows a value changed, in tm diff, without storing it.
  • Secret files are never saved. Names like .env files (except examples), .npmrc, *.pem and *.key are skipped, and so is any file whose content matches a secret pattern. Each one is listed.
  • A tracked file that now holds a secret keeps its last committed version in the save point.
  • Check logs are scrubbed of current secret values. The hooks never store prompt text that looks like a secret, holds a current secret value from your config files, or has a URL with a password in it.
  • Plain values are opt in. Only keys you list in config.plain keep their value, and not even then if the value looks like a secret.

A changed save point fails.

Each save point has one manifest: a JSON file that lists everything it holds. Manifests and verdicts are signed with the key in ~/.timemachine.

A verdict is bound to the exact manifest it was made for, so an old PASS can never stick to a new save point. If a save point was changed after it was saved, its integrity check fails and the verdict is ERROR, not PASS. Save point numbers come from a counter and are never reused.

What the signature does not do

It catches accidental edits, and edits by tools that do not read the key. It does not stop someone who can read ~/.timemachine/key. We do not call it tamper proof.

Network off,
or no check at all.

If you ask for the network to be off and we cannot enforce it, the check does not run. It never quietly runs online instead.

verify, open and find-good work in a separate Git worktree. Your folder and current branch are never touched.

The check gets a clean environment: PATH, HOME, locale, proxy and certificate settings, package manager settings, your config.plain values and CI=1. Nothing else.

With network: deny, the check runs inside a sandbox: sandbox-exec on macOS, bwrap or unshare on Linux. If none is available, the verdict is BLOCKED and tells you how to fix it.

The setup step, like npm ci, always has the network so it can install dependencies. Only the check itself runs offline.

Today this is host mode: a separate copy on your machine, running as you. That is weaker than a container, and every verdict says which mode and network rule it ran with. Container isolation is Planned

Never pushes.
Never merges.
Never deploys.

  • Your state is saved first. Before a recovery, Time Machine saves where you are now as a new save point, so you can always come back to it.
  • A new branch, not your branch. Recover makes tm/recover/<id> and a recovery copy next to your project.
  • You decide when to switch. It does not change your folder or your current branch. The report gives you the commands.
  • Paths stay inside. Restores never write through a symbolic link, and saved paths must stay inside the project.

What this does not protect.

A safety tool that oversells is worse than none. If you find a limit that is not on this list, tell us.

  1. Only captured project state. Databases, deployed versions, emails, payments and anything outside your project folder are not captured.
  2. Host mode is weaker than a container. A check runs as you, on your machine, in a separate copy. Container isolation is Planned.
  3. The signature is not tamper proof against someone who can read ~/.timemachine/key.
  4. Save points are not encrypted. Anyone who can read your disk can read them.
  5. Secret detection uses names and patterns. A secret that matches none of them, or one already committed to Git, is saved like any code.
  6. Setup has the network, even with network: deny. Only the check runs offline.
  7. A PASS proves your check passed. It does not prove your app is correct. The verdict is only as good as the check.
  8. Not a disk backup. Keep one.
  9. No outside security review yet. One is part of why we are raising. Until then, this page is our own account.
  10. Early software. Not on npm yet. The web app runs from a source install with tm ui.
