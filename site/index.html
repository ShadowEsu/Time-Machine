No code needed to get the working version back

Time Machine keeps a copy of your project before the AI touches it, checks which copies still work, and gives you the last good one back. In the web app you use buttons, not commands. Open it with tm ui after a source install.

    Add your project and pick the check

    Point the web app at your project folder. It guesses the command that shows your project works, such as npm test, and you confirm it.

  2. 2

    See which versions work and which broke

    Every change gets a save point. The history shows plainly which ones work and which are broken, and the last one that worked.

  3. 3

    Before anything happens, you see what comes back and what does not, like passwords or your database. The good version then comes back next to your work. Your current folder stays as it was, so nothing is lost, and you can undo the rewind.

More than a commit comes back

A save point is a Git commit pinned under refs/tm, plus a Git bundle in a store outside your project, plus what Git alone would miss. Every recovery report lists both columns, in these words.

Comes back

  • Your code, with uncommitted edits. The commit is made from your working tree, so edits you had not committed yet are in it. Code at commit a1b2c3d
  • Files not in Git. New files you had not added yet, up to a size limit you set. 3 saved files
  • Config, by key name. Keys you allowlist come back with their values. Every other key is kept as its name and a fingerprint, so you can tell what changed without the value ever being stored. Config: PORT
  • Lockfiles. package-lock.json, pnpm-lock.yaml, yarn.lock, Cargo.lock and similar, even when your .gitignore skips them, checked byte for byte against their recorded digests. Dependencies: package-lock.json
  • Environment definition files. Dockerfile, docker-compose.yml, .nvmrc, .tool-versions, .devcontainer/devcontainer.json and similar, also when ignored, also checked against their digests. Environment definition: Dockerfile, .nvmrc
  • A Git bundle in the store. Kept in ~/.timemachine, so the save point survives the project folder being deleted. Runtime versions such as Node and Git are recorded and shown in a compare, not restored.

Does not come back

  • Secret values. Never stored, not even on your own computer. The report names the keys you set again by hand. Secret values in .env: STRIPE_SECRET_KEY
  • Files that look like secrets. An edited tracked file that looks like it holds a secret keeps its last committed version instead. A file named like a secrets file is not saved. .env.local is a secrets file by name, so it was not saved
  • Files your .gitignore skips. Folders like node_modules or build output, unless you ask for them. Files your .gitignore skips were not saved: dist
  • Database contents, deployed versions and external services. Emails sent, payments made, anything on a server. Databases, deployed versions and external services are not captured

Every report ends with the same line: Restored: code, captured files, config. Not restored: database, deployed version, secret values. An unchecked save point is shown as not checked, never as working.

Where Claude Code’s rewind stops

Time Machine runs your own tests on each save point in a separate copy. It brings the working one back on a new branch without touching your folder, and lists what did not come back. It saves before every prompt, and again right before commands like rm -rf and git reset --hard. So an mv or sed -i during a turn can be undone from the save point made before that prompt.

What Claude Code’s checkpointing docs say it does not cover:

  • Files changed by Bash commands are not tracked.
  • Edits made by most subagents are usually not captured.
  • Changes made outside Claude Code, or in other sessions, are normally not captured.
  • Symlinked and hard-linked files are skipped on restore.
  • File snapshots are deleted about 30 days after the session, by default.

Questions

Does it replace Git?

No. It works next to Git. A recovery is a new branch you inspect before you merge it yourself.

Why not the agent’s own rewind?

Claude Code’s docs say checkpointing does not track files changed by Bash commands. Read the Claude Code docs

Does a PASS mean my app is correct?

It means your tests passed. Time Machine never calls a save point working unless your own check passed on it.

What happens after I join?

Your email goes on the list. This site sends no email; Preston writes to the list himself when the CLI is on npm. If the form says the list isn’t open yet, email preston@unvibe.site instead.

Is the web app hosted?

No. tm ui runs on your computer. Your browser talks to it on 127.0.0.1 with a private token that changes each time you start it. Your project is never uploaded, and nothing on it needs a password.
