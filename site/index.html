Install from source and run the demo

The Mac app is still in development. The tm CLI works today on macOS and Linux. Build it from source, then run the demo, or open the same app in your browser with tm ui.

In a terminal Not on npm yet

git clone https://github.com/ShadowEsu/Time-Machine.git
cd Time-Machine
pnpm install && pnpm build
npm install -g ./packages/cli
tm demo

Needs Node 22 or newer and Git. No pnpm? Run npm install -g pnpm first. Keep the Time-Machine folder. The tm command runs from it.

tm demo builds a small synthetic project in a temporary folder, breaks it, then brings back the last version that passed. Your own projects are not touched. In two runs on a Mac with a fresh home folder on 20 October, clone to finished demo took 24 and 45 seconds. Most of that is downloading and building.

tm ui opens Time Machine in your browser. It runs on your own computer at 127.0.0.1, not on a website, so your project is never uploaded. Keep the terminal open while you use it. Tested on macOS so far.

No code needed to get the working version back

Time Machine keeps a copy of your project before the AI touches it, checks which copies still work, and gives you the last good one back. You use buttons, not the terminal.

  1. 1

    See which versions work and which broke

    Every change gets a save point. The app shows plainly which ones work and which are broken, and the last one that worked.

  2. 2

    Dial back to the last version that works

    Before anything happens, you see what comes back and what does not, like passwords or your database.

  3. 3

    Go back in a separate copy

    The good version comes back next to your work. Your current folder stays as it was, so nothing is lost, and you can undo the rewind.

One engine behind the app, the CLI and the hooks

The Mac app, the tm CLI, the Claude Code hooks and the MCP server call the same engine, so their answers always match.

Where Claude Code’s rewind stops

Time Machine runs your own tests on each save point in a separate copy. It brings the working one back on a new branch without touching your folder, and lists what did not come back. It saves before every prompt, and again right before commands like rm -rf and git reset --hard. So an mv or sed -i during a turn can be undone from the save point made before that prompt.

What Claude Code’s checkpointing docs say it does not cover:

  • Files changed by Bash commands are not tracked.
  • Edits made by most subagents are usually not captured.
  • Changes made outside Claude Code, or in other sessions, are normally not captured.
  • Symlinked and hard-linked files are skipped on restore.
  • File snapshots are deleted about 30 days after the session, by default.

Four words you’ll see in the app

Save point
A copy of your project at one moment. Made before each request to the AI and before risky commands.
Check
Your own tests, run on a save point in a separate copy. The answer is Works or Broken.
Go back
The newest save point that works comes back as a separate copy. Your current work stays where it is.
Does not come back
Passwords and keys, databases, anything already published. Every result lists these, so nothing surprises you.

Keep a way back while your agent works

Time Machine is not

  • A backup or a Git replacement. Keep committing, and keep a disk backup.
  • An account or a cloud service. The tm CLI and tm ui run on your computer.
  • A restore in place. You get a separate copy on a new branch.
  • Another approval prompt. The hooks save and check without asking you to approve each step.

Questions

Does it replace Git?

No. It works next to Git. A recovery is a new branch you inspect before you merge it yourself.

Why not the agent’s own rewind?

Claude Code’s docs say checkpointing does not track files changed by Bash commands. Read the Claude Code docs

Does a PASS mean my app is correct?

It means your tests passed. Time Machine never calls a save point working unless your own check passed on it.

What happens after I join?

Your email goes on the list. This site sends no email; Preston writes to the list himself when the CLI is on npm. If the form says the list isn’t open yet, email preston@unvibe.site instead.

What will it cost?

Nothing is for sale. The CLI is free and MIT licensed. Restores will never be behind a paywall.
