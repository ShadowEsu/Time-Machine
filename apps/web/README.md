# Time Machine app: browser and Mac

The shared renderer serves both the local browser app (`tm ui`) and the Mac app. Both call the same `@timetm/core` engine and read the same checkpoint store (`$TM_HOME`, otherwise `~/.timemachine`). The browser app does not require Electron or Apple signing. The Mac app adds a menu-bar item, native folder picker, overlays and a global hotkey.

## Use real projects in the browser

Build the workspace with `pnpm install && pnpm build`, then run `node packages/cli/dist/tm.js ui` (or `tm ui` after installing the CLI). This opens a private local session at `127.0.0.1`; the full address includes a session key and should not be shared. Keep its terminal open. Ctrl+C stops the server.

The browser app accepts a full local Git folder path instead of a native folder picker. It saves, checks, compares and recovers real projects. Claude Code hook and CLI activity updates the page live. `--no-open` skips launching a browser; `--port N` sets the port.

Browser-only differences: no menu-bar item, system-wide shortcut or desktop overlay; optional online features read credentials from the server environment instead of writing plaintext keys. Mac-specific settings remain available in the Mac app. The synthetic-data static preview described below is separate from `tm ui`.

## Run it on a Mac

From the repository root:

```sh
pnpm install
pnpm app
```

`pnpm app` downloads the Electron binary the first time, builds the app into `apps/desktop/out/` and opens it. Node 22.12 or newer is needed.

The Claude Code sidebar refreshes its last completed turn from the real audit log alongside project and connection status. You do not need to visit Agents first to see when the turn ended. The native smoke installs real hook lines and checks that the sidebar updates after an external hook process finishes.

Other scripts, run from the root with `pnpm --filter @timetm/desktop <script>`:

| Script | What it does |
|---|---|
| `dev` | Build and run the app (same as `pnpm app`) |
| `build` | Build the app into `out/` without running it |
| `preview:build` | Build the browser preview into `preview/dist/` |
| `typecheck` | Type check the main process and the window code |
| `signing:setup` | Create or reuse the local self-signed identity on this Mac |
| `package:local` | Build, stage, package and self-sign `release/Time Machine.app`, then zip it |
| `package:release` | Same build, signed with a Developer ID, notarized, stapled and zipped again. Needs `TM_SIGN_IDENTITY` and `TM_NOTARY_PROFILE` (see [Before Apple notarization](#before-apple-notarization)). Not run yet |
| `smoke:native` | Exercise the packaged app with isolated synthetic data: demo verification, focus, announcements and safe recovery (run `package:local` first) |

## Running an unsigned build

This build is not signed or notarized by Apple yet. macOS warns the first time you open it. To open it anyway, do one of these:

- In Finder, Control-click the app, choose Open, then choose Open again.
- Or open System Settings, then Privacy & Security, scroll to the message about the app and click Open Anyway.

Only do this for a build you got from the official GitHub repository, [ShadowEsu/Time-Machine](https://github.com/ShadowEsu/Time-Machine). Apple Developer ID signing and notarization are planned (D08). Until then, a downloaded `Time Machine.zip` is quarantined and Gatekeeper blocks the app; see [Before Apple notarization](#before-apple-notarization). The welcome screen says this is not signed or notarized by Apple.

## Local self-signed Mac package

This is not Apple Developer ID signing. It does not notarize the app or make Apple trust it. The first-open warning and the guidance above still apply to downloaded builds. Apple signing and notarization remain planned (D08).

From the root on a Mac with Node 22.12+, pnpm and OpenSSL 3 installed:

```sh
pnpm --filter @timetm/desktop package:local
```

The script builds `out/`, copies only that output and a minimal `package.json` to a temporary staging folder, and uses the exact `@electron/packager@19.0.1` and Electron version in this package. It does not package this checkout, `node_modules`, the store or signing material. The bundled engine and CLI are already in `out/`. The CLI stays unpacked because hooks run it through a real filesystem path.

Output is `apps/desktop/release/Time Machine.app` and `apps/desktop/release/Time Machine.zip`. The script replaces only these two local artifacts. It does not install in `/Applications`, publish, enroll with Apple or notarize anything. The app keeps bundle ID `dev.timetm.desktop`; helper IDs stay under it.

The app icon is drawn from code by `scripts/app-icon.mjs` (no image tools, fonts or network; same input, same bytes). `build.mjs` writes `out/icon.png` for unpackaged runs. `package:local` builds the `.icns`, sets the version and copyright in `Info.plist`, and fails if the bundle still carries Electron's icon. To look at every size: `node apps/desktop/scripts/app-icon.mjs <dir>`.

`signing:setup` runs automatically when packaging. It makes **Time Machine Self Signed** once, in a dedicated `~/.timemachine-signing/signing.keychain-db`. Future builds unlock and reuse it. The same directory holds an encrypted private key (`private-key.pem`), certificate (`certificate.pem`), encrypted PKCS#12 backup (`identity.p12`) and password file (`password`). Its permissions are 0700, with files 0600. Back up the whole directory privately. Never commit or share it. Losing it means losing this signing identity. Setup resumes incomplete steps without replacing an existing key or certificate.

Trust is user-local, only for code signing. The dedicated keychain is appended to the user keychain search list, preserving every existing entry. No system trust or unrelated identities are changed. The identity has a ten-year certificate. `security` receives the saved password as a process argument for keychain operations; do not run this under shell tracing or log process arguments.

Nested Mach-O code is signed first, then helper and framework bundles, then the app. Hardened runtime is on, with no timestamp. Main and helper executables get V8 JIT permission and the library-validation exception needed by a self-signed Electron app without an Apple Team ID. The app is not App Sandbox signed, so sandbox inheritance entitlements are not added. No unsigned executable memory, camera, microphone or Accessibility entitlement is added.

Check the artifact locally:

```sh
codesign --verify --deep --strict --verbose=2 'apps/desktop/release/Time Machine.app'
codesign -d -r- 'apps/desktop/release/Time Machine.app'
spctl --assess --type execute --verbose=4 'apps/desktop/release/Time Machine.app'
```

The first command must pass. The last is expected to reject this non-Apple-trusted build. A stable designated requirement across rebuilds identifies the same signer and bundle, not proof that macOS privacy permissions persist. That persistence has not been tested.

Exercised locally on 17 October 2026 (Apple silicon): two full packages reused the same certificate and had identical designated requirements. `codesign --verify --deep --strict` passed on the final app. Hardened runtime was present. `spctl` rejected it (exit 3), as expected for this signer.

The packaged `.app` launched through its own executable with isolated HOME, TM_HOME and userData. The real-engine demo reached a passing version and made `tm/recover/cp-0003` in two clicks. The synthetic project kept the same branch, HEAD and working-tree status before and after recovery. The result showed what was not restored. No renderer page errors were observed. Evidence and screenshots: `/tmp/tm-pw/app-selfsigned/`. This did not exercise a quarantined download, Finder's first-open warning or privacy grant persistence.

## Before Apple notarization

Five things block a notarized build. Items 1 and 2 are owner actions and still open. Items 3 to 5 are handled by `package:release` once 1 and 2 exist. That path has not run yet: there is no Developer ID certificate or notary profile on any Mac we use, so it is checked only by unit tests of its argument lists (`test/signing.test.ts`). Until it runs, a downloaded ZIP is Gatekeeper blocked.

1. **Developer ID certificate (open).** A Developer ID Application certificate needs a paid Apple Developer Program team. Today `package:local` signs with the self-signed "Time Machine Self Signed" identity.
2. **Notary credentials (open).** A `notarytool` credential profile on the signing Mac (`xcrun notarytool store-credentials`, with an app-specific password or an App Store Connect API key). None exists.
3. **Secure timestamp (handled by `package:release`).** The default build still signs with `--timestamp=none`. A Developer ID build signs every item with `--timestamp` and hardened runtime.
4. **Library validation entitlement (handled by `package:release`).** A Developer ID build uses `scripts/entitlements.release.plist`, which keeps only `com.apple.security.cs.allow-jit`. Electron's V8 needs JIT under hardened runtime. It drops `com.apple.security.cs.disable-library-validation`: every nested framework and helper carries the same Team ID, so library validation can stay on. The default build keeps `entitlements.local.plist`, because a self-signed build has no Team ID.
5. **Stapling (handled by `package:release`).** After Apple returns Accepted, the script staples the app, then rebuilds the ZIP from the stapled app.

Once 1 and 2 exist, on the signing Mac:

1. Install the Developer ID Application certificate with its private key in the login keychain, plus Apple's intermediate certificate. `security find-identity -v -p codesigning` must list it.
2. Store the notary credentials once: `xcrun notarytool store-credentials tm-notary --apple-id <id> --team-id <TEAMID>` (it asks for an app-specific password), or use `--key`, `--key-id` and `--issuer` for an API key.
3. Run:

   ```sh
   TM_SIGN_IDENTITY="Developer ID Application: <Name> (<TEAMID>)" TM_NOTARY_PROFILE=tm-notary pnpm --filter @timetm/desktop package:release
   ```

`TM_SIGN_IDENTITY` may also be the identity's SHA-1 hash. `package:release` refuses to start unless both variables are set. The script looks up the identity before building and stops if it is missing, ambiguous or not Developer ID. It signs, verifies, zips with `ditto`, then runs `xcrun notarytool submit <zip> --keychain-profile <profile> --wait`. Anything but Accepted stops the build and prints `xcrun notarytool log <id> --keychain-profile <profile>`. Then it runs `xcrun stapler staple` on the app, zips the stapled app again, and checks it with `codesign --verify --deep --strict --verbose=2` and `spctl --assess --type execute -vv`.

With no variables, `package:local` runs exactly the same commands as before. Setting only `TM_SIGN_IDENTITY` makes a Developer ID signed build without notarization. Apple allows 75 notarizations a day.

Not yet known, and to check on the first real run: whether any Electron helper needs more than `allow-jit` without the library validation exception. Launch the stapled app and run `pnpm --filter @timetm/desktop smoke:native` before shipping it.

## What is built

- **Onboarding (D01):** three named steps, one click each. Pick a project folder: setup starts as soon as you pick it, adds `timemachine.yml` (`init`) and makes the first save point. It says "Saved, not checked" until a check runs. Choose the check: the one `init` found is already picked, with a quiet line for the install step that runs first when there is one ("Installs first with npm ci …"). Try it now is optional; changing it uses `setCheck`. Choose when to save: "Connect Claude Code and finish" adds the hook lines (shown first in plain words, the exact lines on request) and finishes, and "Skip, finish without it" finishes without them. If the lines cannot be prepared, or the command does not run on this Mac, Finish is the only button and the step says why. Each step's buttons stay in view on short windows.
- **Try the demo:** the first button on the welcome screen. The real engine builds Marigold Tips in a temporary folder, breaks it and finds the newest passing save point. The app undoes the engine’s recovery branch and copy, then opens Review with one Go back button. It also checks the state saved before that recovery in the background. Leaving Review shows Broken only after that real check fails, not an assumed verdict. Done lists what came back, what did not and what needs to be done by hand.
- **Claude Code hook command:** the build bundles the `tm` CLI into `out/tm.mjs`, and the hooks call it with the app's own Node as quoted absolute paths: `ELECTRON_RUN_AS_NODE=1 '<Electron>' '<out/tm.mjs>'`. If that does not answer, the fallback is `npx -y timetm@<version>`, pinned to the CLI version, never the bare package name. `TM_HOOK_COMMAND` overrides both when the app runs from source. A packaged app ignores it. Before adding any line the app runs `<command> --version` and adds nothing unless it answers with this version. Settings says "connected" only when the lines are there and the command runs, and "connected, but the command does not run yet" when the lines are there but it does not answer. The paths point into this checkout, so moving or deleting it stops the hooks until you connect again.
- **Window frame:** a 268 px rail on paper with the buddy (the small white machine) and the name, "Jump to…" (`⌘K`), Projects (a verdict dot, the verdict word and how long ago each last saved), Add a project, the Agents list (Claude Code only, with our own symbol in the orange family, never a provider's logo, and a short real state, such as "Connected to tips", or Connect beside it when it is not connected; then "More agents coming"), then "History is saved on this computer" (with "Ask sends titles and changes to Gemini" after it when any project has Ask on), the plan card (Free plan with the real number of projects against the limit, or License Active; it opens Settings), Storage (space used) and Settings. - **The end of a check's output:**
  - `checkLogTail {projectId, id}` reads the newest log the engine wrote for that save point (`packages/core/src/logTail.ts`).
  - How the file is picked and read:
    - by its exact `<id>-<stamp>.log` name, not through a link, only a regular file;
    - one positioned read of its last 64 KB.
  - What comes back: at most 20 lines, 300 characters each and 4 KB in all.
  - How the lines are cleaned:
    - terminal escapes, control and bidi characters are stripped;
    - today's `.env` values are redacted again;
    - a line that looks like a key is hidden;
    - a private key, or a secret split over lines, hides the whole tail;
    - a binary tail shows nothing.
  - The page shows the lines as text. They are never sent to Ask, a report or an export.
- **The check record of an earlier verdict:**

A corner card appears only when a project's verdict turns from PASS to FAIL, with "Go back to the 7:03 PM version" (the last one that works, named by its time) and See what changed. Both open the app window on the screen the card was on. The card never takes focus and hides on its own unless you hover it. While Claude Code is in a turn, a small pill at the bottom of the screen says so. It comes from the hook audit lines ("agent-turn started" at each prompt, "ended" at stop) and counts as over after an hour without an end. The timeline strip is in the menu bar menu.
- **Agents, Storage and Settings (D07):** three pages. Agents: Claude Code, with our own symbol, and one intro line: "Claude Code connects through hooks. More agents coming." Claude Code says Working (since when), Idle with the time its last turn ended (from the audit log's "agent-turn ended" lines), Partly connected, or Not connected. Nothing is invented. Under it, Claude Code's connection per project, with Connect after showing what the lines do in plain words; the exact lines, with their long command paths, open under "Show the exact lines" or with Git details on. Storage: space used per project, "Clean up old check logs…" (it explains what goes, lists it first, then offers Never mind, focused, or Remove them, and removes only the files it listed) and Remove from app, which asks first with Never mind focused. Settings: appearance, Show Git details, rewind style, Features per project, the global shortcut that shows the app window (`⌃⌥T` by default, can be changed or turned off), corner cards, agent pill, and where checks run (a safe copy on this Mac, with the network sandbox found). The shortcut needs two modifier keys, one of them Control or Command, and can't be copy, paste, cut, undo, quit, close or select all. Settings are stored as Zod checked JSON in the app's data folder. Every Settings section opens with one line on what it is for; Appearance picks the theme from three tiles (System, Light, Dark), each a small picture of the app in that theme, the picked one outlined in ink. The rail shows each project's purpose icon with an 8 px status dot on its corner and its age in plain words (just now, 3 min, 2 h, Yesterday). Plan has Sign in to get your key: email, a 6-digit code, then the keys bought with that email, each with Use this key (the key itself is never shown); when the site has not opened sign-in it says so, and the paste-key field stays under it.
- **Jump to… (`⌘K`):** Unvibe's search palette: a white card with an ink edge and a hard shadow, a 52 px field, then labelled sections (actions: Save now, Check it works, go back to the last working version, Compare, Agents, Storage, Settings, Reduce motion with On or Off, the same switch as in Settings; projects; the 12 newest save points by time and title) in 44 px rows with the shortcut as a keycap on the right. At 560 px and below a save point's row takes two lines, its time and verdict and then the whole title. Every typed word must match. Arrow keys and Enter, no mouse needed; the row the arrows are on gets a warm tint and an ink accent on the left, like the journal's selected row, with neutral keycaps. The field is a WAI-ARIA combobox: focus stays in it and `aria-activedescendant` names the row the arrows are on, so a screen reader says each row. No match shows the buddy and "Nothing matches …" as a status, outside the list. Esc returns focus to what opened it; opening a save point puts focus on its detail's Not now.
- **Shortcuts (`?`) and ⋯:** the shortcut sheet lists every shortcut that works today in two columns (one below 860 px), each key a sky keycap; Esc returns focus to what opened it (⋯ on a phone), or to the page heading when it was opened from nowhere. The ⋯ menu is a white card with an ink edge and a hard shadow, 44 px rows, shortcuts on the right; Esc returns focus to ⋯, and so does closing anything opened from it.
- **Connect Claude Code:** a sheet with an ink edge and a hard shadow (from Agents' Connect, History's setup strip or "Add the missing lines"): the three lines in plain words, then "Show the exact lines" in the near-black terminal panel with the settings file it writes. Add these lines and Cancel stay in a bar at the sheet's foot; done is a sky card, an error the engine's own words.
- **Inspector (`⌘I`, or ⋯):** a card over the right edge with the raw engine result of the last action and the same action as a `tm` command, with Copy. For the selected save point: the exact commit, its ref, the last check's command, exit code and log (with Show log), and the `tm` commands to check, open, use and compare it. Each result block scrolls on its own and takes keyboard focus. Undo of a rewind has no `tm` command yet, so the Inspector says it is app only.
- **Look:** the Unvibe sibling (Design's direction, 23 Oct): warm paper (`#f4f2ed`) around a white canvas, light first, with a warm charcoal dark mode. New installs follow the system theme. Bricolage Grotesque for the status and headings, Instrument Serif italic only for the page's voice lines (the welcome, a page's one subtitle, "Your folder wasn’t touched."), never for data or section labels, Inter for the record, day headings and rail groups, and IBM Plex Mono for times, ids and commands. No text on History or in the rail is under 13 px; the screens not rebuilt yet keep the old 12 px floor until their turn. Controls are pills with a 1.5 px ink border and a hard offset shadow that press in; keycaps are sky; the focus ring is the brand orange (3 px, 4.2:1 or more on paper and canvas in both themes); on dark the main button is the ink pill inverted, paper with ink text. Green and red mean a recorded verdict (and, in Compare only, an added or a removed file, which also says so in words), and each verdict also has its own shape and word. A row's Bring back is a quiet outlined button. Fonts ship in `src/renderer/fonts/` with their SIL OFL licences; nothing loads from the network.
- **Launch splash:** the paper window with the Time Machine wordmark ("Machine" in the italic voice) and a thin sky loading bar along the bottom edge. It is drawn by `index.html` before any script runs and fades out over 300 ms once the settings, the projects and the first page are drawn, after at least 600 ms so it never flashes. The bar has no percentage. Any key or click skips it, and the key still reaches the app. It shows at launch only, never when you move between pages. With Reduce motion on it does not fade and has no minimum: it is there only while the app loads. The logic is in `src/renderer/splash.ts`.
- **Motion:** a new page fades in and rises 8 px (220 ms). Sheets (the confirm, Shortcuts, Connect, Check), Jump to… and the toast share one surface: a 20 px corner, the 1.5 px ink edge, one of two hard shadows, and one entrance (a 6 px rise from 97 % over 220 ms, a fade under Reduce motion), and they fade out when they close; the Rewind scene, the Inspector and toasts fade out too. What is closing never takes clicks, so nothing waits for it. A project's journal rows rise in one after another the first time the journal shows in a session, with the last row starting at most 300 ms after the first. Only opacity and transform move, so nothing shifts the layout. A redraw in the middle continues the movement instead of restarting it (`src/renderer/motion.ts`). The verdict stamp keeps its own moment. With Reduce motion on, none of this moves.
- **Playheads:** on History the playhead snaps to each save point over 120 ms. When the Rewind opens, its playhead glides from Now to the save point over 420 ms while the dial turns back; each tick it passes flicks once as the playhead crosses it, and a Works save point it lands on rings once. A redraw during a glide resumes it at the same point of its curve, so it never jumps ahead of its flicks. With Reduce motion on, none of these move.
- **Keyboard and announcements:** modal sheets, Rewind, Jump to and Shortcuts move focus inside, contain Tab and Shift+Tab, make the background inert and restore focus on close. Nested dialogs restore their parent before the page. The busy demo sheet has a named dialog and a decorative spinner. One live region survives window redraws and announces demo stages and check results; the toast is its own status region outside the redraw. Controls have at least 40 px hit areas on a desktop and 44 px on a phone, without overlapping adjacent controls.

Every verdict has a shape and a word: Works, Broken, Couldn’t check, Needs something, Check crashed, Not checked yet. Color only confirms. When a shortcut fires, its button shows its pressed state for about 120 ms.
